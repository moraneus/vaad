# הגדרה אופציונלית: 2FA, מייל, Cron, שחזור סיסמה

[← חזרה ל-README](../../README.he.md) · [English](../optional-setup.md)

התוספות האלה עצמאיות — אפשר להפעיל כל תת-קבוצה.

## אימות דו-שלבי (2FA) למנהל הראשי

1. היכנס כמנהל ולך ל-**הגדרות → אבטחה וסיסמאות → אימות דו-שלבי → הפעל**.
2. הדיאלוג מציג מפתח Base32 + URL `otpauth://`. פתח את Google Authenticator (או Authy / 1Password / Microsoft Authenticator) בטלפון והוסף חשבון *ידנית* על ידי הדבקת המפתח.
3. הקלד את הקוד 6 ספרות מהאפליקציה ולחץ **אמת והפעל**.
4. **שמור את קודי הגיבוי שמוצגים בעקבות** — הם קודי חירום למקרה שתאבד את הטלפון, ומוצגים פעם אחת בלבד.
5. מעכשיו, כניסת מנהל דורשת סיסמה **וגם** קוד עדכני מהאפליקציה.

לכיבוי 2FA תזדקק גם לסיסמת המנהל וגם לקוד עדכני (או קוד גיבוי) — מונע ממי שגנב את ה-session לכבות את ההגנה.

> אדמיני־דירה משתמשים רק בסיסמה. ההפעלה של 2FA היא ברמת המערכת — מגנה רק על המנהל הראשי. כניסה עם Google **חסומה למנהל הראשי** כש-2FA מופעל (single-factor OAuth היה עוקף את הגורם השני).

## התראות מייל דרך Resend (חינמי)

הירשם ב-[resend.com](https://resend.com) — החבילה החינמית נותנת 3,000 מיילים בחודש.

> ⚠️ **חשוב — נדרש domain משלך לשליחת מייל אמיתית.**
>
> Resend (כמו כל שירות מייל transactional מכובד) דורש שכתובת השולח תהיה ב-domain שאימתת. **אי אפשר לשלוח מ-`@gmail.com`, `@outlook.com`** או כל ספק אחר שאינו שלך.
>
> שלוש דרכים לפתרון:
> 1. **לוותר על מייל לגמרי.** המערכת עובדת מצוין בלי זה.
> 2. **לבדוק עם `onboarding@resend.dev`.** רק שולח לכתובת איתה נרשמת ל-Resend.
> 3. **לרכוש domain זול (~$10/שנה).** Cloudflare Registrar, Porkbun, Namecheap.

### 1. צור API key

ב-Dashboard של Resend → **API keys → Create API key** → העתק את הערך (`re_...`).

### 2. הוסף שולח — בחר אחד משלושה מודים

**(א) sandbox ברירת מחדל (לבדיקות):** השתמש ב-`onboarding@resend.dev`. ללא הגדרה. מוגבל למייל של חשבון Resend שלך.

**(ב) Domain אישי שלך (פרודקשן):**
- ב-Resend → **Domains → Add Domain** → הזן את ה-domain.
- Resend ייתן רשומות DNS (SPF, DKIM, DMARC). הוסף אצל הרגיסטר.
- חכה 5-30 דקות לאימות.
- עכשיו אפשר לשלוח מכל כתובת ב-domain, למשל `vaad@yourdomain.co.il`.

**(ג) Subdomain על domain של חבר:** ביקוש subdomain כמו `vaad.theirdomain.co.il`.

### 3. הוסף את ה-secrets ל-Cloudflare

```bash
cd <path-to-project>
npx wrangler pages secret put RESEND_API_KEY --project-name=<cf-pages-project>
# הדבק את ה-re_... key

npx wrangler pages secret put EMAIL_FROM --project-name=<cf-pages-project>
# הדבק את כתובת השולח, למשל vaad@yourdomain.co.il
# (או onboarding@resend.dev לבדיקה)

# אופציונלי: שם תצוגה (ברירת מחדל "Vaad Bayit")
npx wrangler pages secret put EMAIL_FROM_NAME --project-name=<cf-pages-project>
# למשל: "ועד הבית של רחוב הרצל 5"

# פריסה מחדש כדי לקלוט את ה-secrets
npx wrangler pages deploy ./public --project-name=<cf-pages-project>
```

### 4. בדוק שזה עובד

היכנס כמנהל → **הגדרות → אינטגרציות → התראות מייל → שלח מייל בדיקה**. אם הגיע — סיימת.

### 5. הסבר לדיירים

כל דייר נרשם לעדכוני מייל מ-**הגדרות → אימייל לעדכונים → הירשם**, או שהמנהל יכול להזין עבורם את האימייל בעת הוספה/עריכה של דירה.

מנהל יכול:
- **לשלוח דוח חודשי** (ידנית) — הגדרות → אינטגרציות → שלח דוח חודשי.
- **לשלוח הודעה לכל הדיירים** — הגדרות → אינטגרציות → שלח הודעה לכל הדיירים.

כל מייל כולל footer "אינו דואר זבל" והוראות הסרה; תאריך ההסכמה נשמר אוטומטית.

### בעיות נפוצות

- **`The domain gmail.com is not verified`** — הגדרת `EMAIL_FROM=you@gmail.com`. עבור ל-(א) או (ב).
- **`The domain example.com is not verified`** — DNS לא הושלם.
- **המייל לא מגיע** — בדוק spam.

## Cron חודשי אוטומטי

Cloudflare Worker עצמאי שיורה פעם בחודש ומריץ **שתי** משימות תחזוקה ע״י קריאה ל-Pages endpoints עם סוד משותף:

1. **הארכה אוטומטית של הוצאות חודשיות** — לכל הוצאה חודשית שהמנהל סימן בה את ה-opt-in להארכה אוטומטית, ה-Worker דוחף את `endDate` קדימה לסוף החודש החדש. כך שורה אחת נשארת מקור האמת להוצאה רציפה ומתחדשת מאליה.
2. **דוח חודשי במייל** — מייצר ושולח דוח PDF במייל לדיירים שנרשמו, דרך Resend.

**Cloudflare Pages Functions לא תומך ב-scheduled triggers**, אז משתמשים ב-Worker כ-scheduler דק. שתי המשימות חולקות את אותו `CRON_SECRET`.

### 1. צור סוד משותף

```bash
openssl rand -base64 32
# העתק את הפלט — תדביק אותו פעמיים (Pages + Worker).
```

### 2. הגדר אותו ב-Pages

```bash
cd <path-to-project>
npx wrangler pages secret put CRON_SECRET --project-name=<cf-pages-project>
# הדבק את הערך משלב 1
npx wrangler pages deploy ./public --project-name=<cf-pages-project>
```

### 3. פרוס את ה-Worker (תיקייה אחות מומלצת)

```bash
mv <path-to-project>/worker <path-to-cron-worker>
cd <path-to-cron-worker>
ls
# cron-monthly-report.js  wrangler.toml

npx wrangler secret put CRON_SECRET
# הדבק את אותו הערך משלב 2

npx wrangler secret put PAGES_ORIGIN
# הדבק את כתובת ה-production, למשל https://<cf-pages-project>.pages.dev

npx wrangler deploy
```

חפש `schedule: 0 8 1 * *` בפלט — ה-cron יורה ב-1 בכל חודש ב-08:00 UTC (≈ 11:00 ישראל).

### 4. בדיקה ידנית (אופציונלי)

ל-Worker יש שני triggers ידניים (שניהם מאומתים עם אותו `x-cron-secret`):

```bash
# /run — מפעיל את שתי המשימות (כמו הלו"ז המתוזמן)
curl -X POST -H "x-cron-secret: <CRON_SECRET_שלך>" \
  https://<cf-cron-worker>.<cf-account-subdomain>.workers.dev/run

# /run-extend — מפעיל רק את משימת ההארכה (לבדיקה ממוקדת)
curl -X POST -H "x-cron-secret: <CRON_SECRET_שלך>" \
  https://<cf-cron-worker>.<cf-account-subdomain>.workers.dev/run-extend
```

| תגובה | משמעות |
|---|---|
| `{"extend":{"status":200,"body":"..."},"report":{"status":200,"body":"..."}}` | שתי המשימות רצו — ראה body של כל אחת לפרטים |
| `{"ok":true,"extended":N,"target":"YYYY-MM-DD"}` (מ-`/run-extend`) | endDate הוארך עבור N הוצאות חודשיות עד התאריך הזה |
| `{"ok":true,"sent":N,"year":Y,"month":M}` | דוח חודשי נשלח ל-N דיירים |
| `{"error":"אין דיירים שרשומים..."}` | תקין, אין נרשמים עדיין |
| `{"error":"Forbidden"}` | `CRON_SECRET` לא תואם בין Pages ל-Worker |
| `{"error":"שירות האימייל לא הוגדר..."}` | `RESEND_API_KEY` / `EMAIL_FROM` לא הוגדרו ב-Pages |
| `{"error":"Resend batch: 403 — ... domain ... is not verified"}` | `EMAIL_FROM` מצביע ל-domain שלא אימתת |

> **בלי ה-Cron Worker**, שתי המשימות נשארות ידניות: המנהל לוחץ **שלח דוח חודשי** מההגדרות, ומאריך את `endDate` של הוצאות חודשיות ידנית (או מציב תאריך עתידי רחוק) במקום להסתמך על הארכה אוטומטית.

## שחזור סיסמה (מנהל ראשי, דירה, ובעלי דירה)

מערכת השחזור היא **פר-משתמש** — לא משותפת:

- **המנהל הראשי** רושם את חשבון Google שלו.
- **כל דירה** (שוכר, דירה-מנהלת) רושמת חשבון משלה — שונה מהמנהל הראשי, ושונה מכל דירה אחרת.
- **כל בעל דירה first-class** רושם חשבון משלו — בלתי תלוי בדירות שהוא מחזיק.

השחזור נעשה דרך **Google OAuth** — המשתמש מתחבר עם חשבון Google שרשם, ובהתאמה מוצלחת הוא נוחת ישירות בעמוד שבו בוחרים סיסמה חדשה. **לא נשלח שום מייל.**

**דרישות:** המשתמש כבר אימת חשבון Google ב-הגדרות → אבטחה → אימות זהות, וה-OAuth client של Google מוגדר.

### זרימה — מנהל ראשי

1. מסך כניסה, לשונית **מנהל**.
2. **"שכחתי סיסמה?"** מתחת לשדה הסיסמה.
3. **"התחבר עם Google"** במודאל.
4. התחבר עם חשבון השחזור.
5. בהתאמה → טופס סיסמה חדשה.

### זרימה — דירה / בעל דירה

1. מסך כניסה, לשונית **דייר** או **בעלים**.
2. בחר את הדירה / הבעלים — קישור **"שכחתי סיסמה?"** יופיע.
3. לחץ עליו, ואז **"התחבר עם Google"**.
4. התחבר עם חשבון Google שנרשם לדירה / לבעלים הזה.
5. בהתאמה → טופס סיסמה חדשה לאותו משתמש בלבד.

### השפעות בעקבות שחזור מוצלח

- שחזור מנהל ראשי: כל הסשנים של המנהל הראשי מנותקים; **2FA מבוטל אוטומטית** (סיבה: מי ששכח סיסמה לרוב איבד גם את ה-authenticator — כיבוי 2FA מונע נעילה לצמיתות; ניתן להפעיל מחדש).
- שחזור דירה / בעלים: רק הסשנים של אותו משתמש מנותקים.

### החלפת חשבון לאיפוס

הגדרות → אבטחה → "החלפת חשבון לאיפוס" מריץ OAuth עם `purpose=replace`. הכתובת הנוכחית מוחלפת **רק לאחר אימות מוצלח של חשבון Google החדש**.

### מניעת ניצול

ה-endpoint של reset מוגבל לפי IP (5 בקשות / 5 דקות). חשבון Google לא תואם נרשם ב-audit log תחת `identity_reset_mismatch`.

### אם שחזור המנהל הראשי לא זמין

תיכנס למצב הזה רק אם מחקת את חשבון השחזור (או מעולם לא רשמת אחד). חלופה:

```bash
# מחיקת ה-hash הקיים כדי שהכניסה הבאה תעבור דרך מסלול "התקנה ראשונה":
npx wrangler d1 execute <your-d1-name> --remote --command \
  "UPDATE admin_auth SET password_hash = 'NEEDS_INIT', password_salt = 'NEEDS_INIT' WHERE id = 1"
```

לאחר ריצה, היכנס עם `1234`, אמת מחדש חשבון לשחזור בהגדרות, ואז שנה סיסמה.

### אם דייר לא מצליח לשחזר את סיסמת הדירה

המנהל הראשי יכול לאפס את סיסמת כל דירה מ-**הגדרות → סיסמאות דיירים → אפס**. הסיסמה החדשה תוצג למנהל דרך מנהל הסיסמאות.

## ללא מייל (Resend)

המערכת **שמישה לחלוטין בלי Resend**:

- **מה ממשיך לעבוד:** כל פיצ'ר של מנהל ודייר ב-UI — תשלומים, הוצאות, דוחות, קבלות, תזכורות, "אודות", שינוי סיסמה, **שחזור סיסמה** (Google OAuth), 2FA.
- **מה תאבד:** דוח חודשי במייל, ברודקאסט אדמין לדיירים, רישום מייל לדיירים.

הכפתורים בהגדרות (שלח מייל בדיקה / שלח לכל הדיירים / שלח דוח חודשי) יציגו `שירות האימייל לא הוגדר` אם תלחץ עליהם. בלי קריסה, רק הודעה ברורה.
